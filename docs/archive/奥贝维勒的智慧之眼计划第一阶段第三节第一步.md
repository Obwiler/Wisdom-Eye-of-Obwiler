### 0.3 场景差异与功能取舍

AndroidWatch_ADB_ToolBox 是面向**智能手表**的 ADB 工具箱，WEO PC 工具面向**智能眼镜**。两者共享 ADB 底层能力，但使用场景和需求不同。下表逐项分析参考工具的功能在眼镜场景下的适用性：

| 参考工具功能 | 手表场景用途 | 眼镜场景分析 | WEO 是否引入 |
|------------|------------|------------|------------|
| 应用商店（100+ APK） | 手表应用生态分散，需集中分发入口 | 眼镜同样需要——除 WEO 外，文件管理器/浏览器/输入法等基础应用也需安装 | ✅ 引入，但**筛选而非照搬**（见 5.3 节） |
| 截图预览 | 手表屏幕小，PC 端放大查看 | 完全相同需求——眼镜 MicroLED 屏 480×640，PC 预览更有价值 | ✅ 引入，改 QPixmap 内嵌 |
| 文件管理 | 手表存储小，需定期清理 | 完全相同需求——WEO 照片、配置文件均在 /sdcard | ✅ 引入，改树形浏览 |
| ADB Shell | 开发者调试命令 | 完全相同需求——查看日志、手动触发广播、调试 WEO | ✅ 引入，加快捷命令 |
| 设备信息 | 型号+系统版本 | 眼镜需要更全面——电池/存储/内存/WEO 专属状态 | ✅ 引入，扩展为 Dashboard |
| 无线 ADB 记忆 | WiFi 调试免插线 | 完全相同需求——眼镜插线不便 | ✅ 引入，JSON 持久化 |
| Fastboot 刷机 | 手表刷 ROM/Recovery | **眼镜不需要**——无刷机场景，WEO 不涉及 Bootloader | ❌ 不引入 |
| ADB 触摸模拟 | 手表小屏点击 | **眼镜不需要**——RG_Glasses 用物理按键，无触摸屏 | ❌ 不引入 |
| 圆屏/方屏分类 | 手表两种屏幕形态 | **眼镜不需要**——仅 480×640 单屏 | ❌ 不引入 |
| pygame 交互 | 手表桌面模拟 | **眼镜不需要**——投屏已由 scrcpy 覆盖 | ❌ 不引入 |

**结论**：通用 ADB 能力（截图/文件/Shell/设备信息/无线连接）直接引入，仅换 UI 技术栈（tkinter → PySide6）；手表专属功能不引入；WEO 在此基础上增加眼镜独有的 AI 配置/一键部署/投屏/指环能力。

### 2.4 核心层接口契约

```python
# AdbClient — 命令客户端
class AdbClient:
    def __init__(self, adb_path: str): ...
    def verify(self) -> bool                              # 启动校验
    def devices(self) -> list[dict]                       # 设备列表
    def shell(self, serial: str, cmd: str) -> tuple[int, str, str]  # (code, stdout, stderr)
    def push(self, serial: str, local: str, remote: str) -> bool
    def pull(self, serial: str, remote: str, local: str) -> bool
    def install(self, serial: str, apk: str) -> bool
    def uninstall(self, serial: str, pkg: str) -> bool
    def screenshot(self, serial: str) -> bytes

# DeviceManager — 设备状态中心 (QObject + Signal)
class DeviceManager(QObject):
    device_changed = Signal(DeviceInfo)
    device_lost = Signal()

    def refresh(self) -> DeviceInfo
    def quick_poll(self) -> bool

# AppCatalog — 应用目录
class AppCatalog:
    def load(self, json_path: str, cache_dir: str) -> None
    def search(self, query: str) -> list[AppMeta]
    def filter(self, category: str, screen: str) -> list[AppMeta]
```

### 5.3 APK 筛选策略

参考工具的 100+ APK 不能直接照搬——那是手表应用生态，大量应用（运动健康、圆屏适配版、抬腕系列）在眼镜上无意义。迁移时按以下规则筛选：

| 筛选维度 | 保留 | 排除 | 原因 |
|---------|------|------|------|
| 应用类型 | 工具/浏览器/输入法/文件管理/音乐/阅读 | 运动/健康/支付/社交/电话 | 眼镜没有 GPS/心率/NFC/蜂窝 |
| 屏幕适配 | 通用 Android / 方屏版 | 圆屏专用版 | 眼镜为 480×640 方屏 |
| UI 交互 | 适配物理按键或通用触摸 | 依赖触摸滑动/手势 | 眼镜仅物理按键 |
| 权限需求 | 不依赖 GPS/电话/短信 | 需要 GPS/电话/短信/蓝牙 | 这些硬件眼镜没有或不开放 |
| Android 版本 | minSdk ≤ 31 | minSdk > 31 | 眼镜运行 Android 12 |
| 来源合规 | 官方原版/自由分发 | 破解/修改版 | 版权风险 |

筛选后预计保留 **30-40 个** 通用应用（约为参考工具总量的 1/3），集中在：输入法、文件管理、浏览器、音乐播放器、阅读器、天气、计算器、单位转换等基础工具类。

### 6.3 app_catalog.json 自动生成逻辑

```
scan_apk_cache.py 流程:
  1. 遍历 lib/apk_cache/ 下所有子目录
  2. 对每个 .apk 文件执行 aapt dump badging
  3. 提取: package: name, versionName, versionCode, sdkVersion
  4. 提取: application: label
  5. 检查目录下是否有 icon.png，无则从 APK 中提取
  6. 按目录名推断分类（需维护一个映射表）
  7. 输出 app_catalog.json
```

## 八、不做的
## ═══════════════════════════════════════

- ❌ 不做 Fastboot 刷机模式 — 眼镜无刷机场景，WEO 不涉及 Bootloader
- ❌ 不做 ADB 触摸模拟 — RG_Glasses 无触摸屏，操作全走物理按键
- ❌ 不做圆屏/方屏分类筛选 — 眼镜仅 480×640 单屏形态
- ❌ 不做多设备同时管理 — 眼镜单人单设备场景
- ❌ 不做应用商店在线更新 — 全离线场景，APK 缓存在本地
- ❌ 不做 ADB over TCP 自动配置 — 无线 ADB 需用户在设备端手动开启，工具仅做记忆重连
- ❌ 不做手表专属应用的兼容适配 — 不引入运动/健康/支付/社交类手表 APK
- ❌ 不做插件系统 — 模块化设计已足够扩展
- ❌ 不换 Electron/Web 技术栈 — PySide6 包体积 ~65MB，远小于 Electron
- ❌ 不引入数据库 — JSON 文件足够
- ❌ 不做国际化 — 目标用户中文

## 九、风险与缓解
## ═══════════════════════════════════════

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| scrcpy SDL 窗口类名变更导致嵌入失败 | 低 | 高 | 备选类名列表 + 超时回退到独立窗口模式 |
| aapt 二进制在部分 APK 上解析失败 | 中 | 中 | 解析失败时用 APK 文件名作为应用名，手动补充元数据 |
| 筛选后的 APK 在 RG_Glasses 上仍可能不兼容 | 中 | 低 | 应用商店仅为安装入口；每张卡片标注最低 SDK 版本和屏幕要求；用户自行判断 |
| PySide6 在部分 Windows 版本上渲染异常 | 低 | 中 | 使用 Qt 6.5 LTS；测试 Win10/Win11 双版本 |
| 参考工具 APK 缓存有版权问题 | 中 | 高 | 只迁移自由分发/官方原版 APK，排除破解/修改版；元数据中用 `source` 字段标注来源 |
