## 五、对照旧项目真视之眼

| 维度 | 旧项目（稳定） | 新项目（问题） |
|------|-------------|-------------|
| 定时轮询 | QTimer 每 5 秒，但**仅刷新 StatusBar 显示**，ADB 调用在 QTimer callback 中同步执行（同方案，但旧项目没有 ApkPanel 轮询，负担更轻） | QTimer 每 5 秒执行 3 次 ADB 调用（StatusPanel × 2 + ApkPanel × 1） |
| QMessageBox | **无**——旧项目通过状态栏文本显示结果，不弹窗 | 3 处无条件弹窗 |
| scrcpy 停止 | `terminate()` + `kill()`，无 `waitForFinished` | `waitForFinished(3000)` 阻塞 3 秒 |
| scrcpy 分辨率 | 在嵌入前异步查询后缓存 | 每次启动同步查询 |
| ADB 线程 | DeviceManager 不继承 QObject，无信号——简单同步模式 | AdbBridge 同样同步，但被更多地方调用 |

**旧项目"能跑"的原因：** ① 代码量小，ADB 调用频次低 ② 无弹窗 ③ StatusBar 轮询负担轻（仅 1 个 panel）。新项目多了 ApkPanel 轮询、config_panel 推拉、ring 按键 ADB 调用、providers.json 加载等额外负担，放大了主线程阻塞效应。

## 六、修复方案（非打补丁，架构级调整）

### 6.1 根除定时器主线程阻塞

```
当前：QTimer(timeout) → _on_timer() [主线程]
                        ├─ status.refresh() [主线程] subprocess.run() × 2
                        └─ apk_panel.refresh() [主线程] subprocess.run() × 1

修复：QTimer(timeout) → _PollWorker(QThread)
                        └─ run():
                            ├─ first_online()
                            ├─ get_device_info()
                            └─ is_installed()
                           emit result → _on_poll_result [主线程] 仅更新 UI
```

### 6.2 配置推拉 + 指环按键 + 启动扫描 → 全部移入 QThread

所有 `subprocess.run()` 调用必须只出现在 QThread.run() 或 QProcess 中。

### 6.3 弹窗策略

- 部署成功 → 改为**日志行显示**，不弹窗
- 部署失败 → 保留弹窗（用户需要知道失败原因）
- 诊断 → 在**状态栏**或日志面板显示，不弹窗
- 所有模态对话框改为非模态或日志行

### 6.4 轮询间隔

- 定时轮询间隔从 5 秒放宽到 15 秒（设备状态变更不频繁）
- 首次扫描完成后才启动定时器（而非构造时就绑定）

### 6.5 scrcpy 停止

```
当前：terminate() → waitForFinished(3000)  ← 同步阻塞
修复：terminate() → finished 信号 → 清理 UI  ← 异步
```
