## 三、S2S2 — IMU 传感器集成
## ═══════════════════════════════════════

### 3.1 背景

第一节审计结论第 6 条明确指出：旧项目的 IMU 500ms 超时必定失败。新方案必须在相机启动时就开始采集 IMU 数据，拍照时直接读取最近值。

当前 handleShutter 调用 ImagePipeline.process() 时传入了 `pitchDeg=0f, rollDeg=0f`——IMU 数据完全未生效。

### 3.2 任务清单

| 编号 | 任务 | 产出物 |
|------|------|--------|
| I01 | 实现 ImuCollector — 加速度计 + 陀螺仪互补滤波器 | `sensor/ImuCollector.kt` |
| I02 | WEOApplication 中启动 ImuCollector | `app/WEOApplication.kt` |
| I03 | CameraScreen 进入时开始采集，退出时暂停 | `ui/screen/CameraScreen.kt` |
| I04 | handleShutter 中读取最新 IMU 值传入 ImagePipeline | `MainActivity.kt` |

### 3.3 ImuCollector 接口设计

```kotlin
interface ImuProvider {
    val pitchDeg: Float    // 最近俯仰角
    val rollDeg: Float     // 最近横滚角
    fun start()
    fun stop()
}
```

实现方案：在 `SensorManager` 上注册 `TYPE_ROTATION_VECTOR` 或 `TYPE_GAME_ROTATION_VECTOR`。相比旧项目用加速度计+陀螺仪手动互补滤波，直接用 Android 内置的旋转矢量传感器更简单、延迟更低。Rokid Glass2 运行 Android 12，`TYPE_ROTATION_VECTOR` 在所有 Android 设备上可用。

### 3.4 核心实现逻辑

```kotlin
class ImuCollector(context: Context) : ImuProvider, SensorEventListener {
    private val sensorManager = context.getSystemService(Context.SENSOR_SERVICE) as SensorManager
    private val rotationSensor = sensorManager.getDefaultSensor(Sensor.TYPE_ROTATION_VECTOR)
        ?: sensorManager.getDefaultSensor(Sensor.TYPE_GAME_ROTATION_VECTOR)

    @Volatile override var pitchDeg = 0f; private set
    @Volatile override var rollDeg = 0f; private set

    override fun start() {
        sensorManager.registerListener(this, rotationSensor, SensorManager.SENSOR_DELAY_UI)
    }

    override fun stop() {
        sensorManager.unregisterListener(this)
    }

    override fun onSensorChanged(event: SensorEvent) {
        val matrix = FloatArray(9)
        SensorManager.getRotationMatrixFromVector(matrix, event.values)
        val orientation = FloatArray(3)
        SensorManager.getOrientation(matrix, orientation)
        pitchDeg = Math.toDegrees(orientation[1].toDouble()).toFloat()
        rollDeg = Math.toDegrees(orientation[2].toDouble()).toFloat()
    }

    override fun onAccuracyChanged(sensor: Sensor?, accuracy: Int) {}
}
```

### 4.3 两种接入路径

取决于 Rokid 审核通过后开放什么接口：

**路径 A：灵珠 Agent 做中间代理**

```
拍照 → APK 通过 CXR SDK 调用灵珠 Agent → Agent 转发到用户配置的 AI → 返回结果
```

优势：APK 不需要自己发 HTTP 请求，Agent 负责模型路由。劣势：依赖 Rokid 平台稳定性。

**路径 B：CXR SDK 仅做按键通道**

```
拍照 → APK 直接 HTTP 调用用户配置的 AI 服务商 → 返回结果（当前已实现）
CXR Bridge → 仅用于指环按键映射（替代当前 BroadcastReceiver 方案）
```

优势：不依赖灵珠 Agent 的 AI 转发能力，当前 HttpAiClient 无需改动。

**建议**：优先实现路径 B（按键通道），Agent AI 转发作为后续可选项。这样即便灵珠 Agent 审核未通过或功能受限，指环按键映射仍然可用。

### 5.2 密钥生成

```bash
keytool -genkey -v \
  -keystore weo-release.keystore \
  -alias weo \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <用户设定> -keypass <用户设定>
```

密钥文件存放于 `data/` 目录（不在 apk 子目录中，防止误提交）。

### 5.3 构建流程

```
1. 确保 data/weo-release.keystore 存在
2. 填写 keystore.properties（storePassword, keyAlias, keyPassword）
3. ./gradlew clean assembleRelease
4. 复制 APK → pc_tool/lib/apk/
5. PyInstaller 构建 EXE
```
