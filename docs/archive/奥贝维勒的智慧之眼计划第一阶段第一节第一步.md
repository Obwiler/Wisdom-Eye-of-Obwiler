### 1.2 产品定位

一款运行在 **Rokid AR 眼镜**（Glass2 / Glasses 系列）上的智能识图工具。用户佩戴眼镜拍摄题目/文本/场景，照片经用户自行配置的 AI 大模型分析后，返回解答或翻译结果，呈现在眼镜 MicroLED 屏幕上。

### 1.3 分发策略

- **主要：线下直接分发 APK**
- 暂不考虑海外市场、Google Play
- 国内应用商店（华为/小米/应用宝）作为后续可选项
- 配合 PC 管理工具使用（USB ADB 配置）

### 1.4 合规基础

- 源码许可证：MIT License
- PC 端 GUI 框架：PySide6（LGPL，可闭源分发）
- Android 依赖：全部 Apache 2.0，无 GPL 传染
- 隐私政策：待生成，见 `compliance/PRIVACY_POLICY.md`
- 签名密钥：全新生成，密码不纳入版本控制

## 二、旧项目审计结论
## ═══════════════════════════════════════

以下 10 条经验来自对 `F:\TOOLS\OculusVeritatis` 的全量审计（r1-r7），新项目以此为戒：

| # | 问题 | 旧项目表现 | 新项目对策 |
|---|------|-----------|-----------|
| 1 | **矩阵变换硬编码** | CameraSurfaceBinder 经历 4 个版本全部失败（旋转方向错误、比例崩解、pivot 不一致） | 使用 Android 标准 `Matrix.setRectToRect()` API，不手算旋转参数 |
| 2 | **相机生命周期竞态** | DisposableEffect 交叉释放/重开导致 1-2 秒黑屏 | CameraHolder 单例由 Activity 持有，Composable 只做 Surface 绑定 |
| 3 | **Compose State 跨协程失效** | `while(shutterPressed)` 循环永远读到 false | 使用 `Channel<Unit>` 做协程间事件通信，不用 State 轮询 |
| 4 | **配置推送杀进程** | force-stop + am start 中断用户操作 | 广播 `CONFIG_UPDATED` + FileObserver 静默刷新 |
| 5 | **硬编码尺寸/URL** | 640×480、API 端点、服务商映射全写死 | 运行时从系统 API 读取，配置从 JSON 文件加载 |
| 6 | **IMU 采集超时** | `withTimeout(500ms)` 必定在传感器启动前超时 | 相机打开时即开始采集，拍照时取最新值（<100ms） |
| 7 | **错误信息同质化** | 无网 / Key错 / 超时 / 服务宕 → 全部显示"AI 服务暂不可用" | 异常分层分类，每类给出可操作的指导信息 |
| 8 | **JPEG 多次重压缩** | quality 75→65→55→45→35 最多 5 次 | 一次 quality=60，超标直接降 quality=40，最多 2 次 |
| 9 | **快门触发不可靠** | LaunchedEffect + State 双重触发不可控 | Channel 事件总线，单一入口 |
| 10 | **PC 端 GPL 闭源违规** | PyQt6 = GPLv3，闭源分发违法 | PySide6 = LGPL，允许闭源分发 |

### 可参考但不可照搬的资产

| 旧模块 | 新项目处理方式 |
|--------|--------------|
| ImageProcessor（透视变换+直方图拉伸） | 参考算法思路，重新组织为 `image/` 模块，去硬编码 |
| ImuProvider（加速度计+陀螺仪互补滤波） | 参考采集逻辑，重新组织为 `sensor/` 模块 |
| AiServiceImpl（OkHttp + JSON 请求） | 参考 HTTP 调用方式，完全重写为接口驱动 |
| scrcpy 工具链（二进制文件） | 直接复制到新 pc_tool |
| Camera2Service | **不参考**，从头设计 CameraHolder 单例 |

## 三、架构设计
## ═══════════════════════════════════════

### 3.1 核心理念

**四层脱耦架构：** 层之间仅通过接口通信，具体实现可在不修改调用方的前提下替换。

```
┌─────────────────────────────────────────┐
│              UI Layer                   │  Compose Screens
│  HomeScreen / CameraScreen /            │  只持有接口引用，
│  ResultScreen / SettingsScreen          │  不直接依赖实现
├─────────────────────────────────────────┤
│           Application Layer            │  ViewModel / State
│  EventBus / ConfigHolder /             │  跨层通信
│  NavController                         │
├─────────────────────────────────────────┤
│            Service Layer               │  纯接口定义
│  CameraService / AiService /           │  实现可交换
│  ImageService / SensorService          │
├─────────────────────────────────────────┤
│          Infrastructure Layer          │  Android 系统 API
│  Camera2 / OkHttp / SensorManager /    │  不向上暴露
│  FileSystem                           │
└─────────────────────────────────────────┘
```

### 3.2 接口契约（Service Layer）

```kotlin
// 相机服务 — 单一持有者，不随 Composable 生命周销毁
interface CameraService {
    val previewSize: Size       // 运行时从 CameraCharacteristics 读取
    val sensorOrientation: Int  // 运行时从 CameraCharacteristics 读取
    fun bindSurface(surface: SurfaceTexture)
    suspend fun capture(): ByteArray
    suspend fun awaitReady()
}

// AI 服务 — 用户配置驱动，不内置任何服务商凭据
interface AiService {
    suspend fun analyze(
        image: ByteArray,
        config: AiConfig,       // 用户填的 API URL + Key + Model
    ): AiResult
}

// 配置服务 — FileObserver 热更新，无需重启
interface ConfigService {
    fun load(): AiConfig
    fun observe(onChange: (AiConfig) -> Unit)
}
```

### 3.3 事件总线

所有跨协程通信使用 `kotlinx.coroutines.channels.Channel`：

```kotlin
object AppEvents {
    val shutterRequest = Channel<Unit>(Channel.CONFLATED)   // 快门按下
    val configUpdated = Channel<Unit>(Channel.CONFLATED)    // 配置刷新
    val navigateTo = Channel<Screen>(Channel.CONFLATED)     // 导航请求
}
```

### 3.4 AI 模型策略

**用户自己带 Key，APK 不做中间代理。** 

APK 只负责：拍照 → 发 HTTP POST 到用户填的 URL → 显示返回。不内置任何免费模型、不存任何服务商凭据、不做额度管理。

用户通过 PC 管理工具（或未来 APK 设置页）配置：
- API Base URL（如 `https://api.deepseek.com/v1`）
- API Key（用户自己的）
- Model Name（如 `deepseek-chat`）
- System Prompt（留空则用内置默认）

## 七、不编码原则
## ═══════════════════════════════════════

1. **所有尺寸从系统 API 读取：** 相机分辨率 → `CameraCharacteristics`、屏幕尺寸 → `BoxWithConstraints`、设备名称 → `Build.MODEL`
2. **所有 URL/端点从配置文件读取：** 不在 Kotlin/Python 源码中写死任何第三方服务的完整地址
3. **所有密钥/密码不入代码库：** `.gitignore` 排除，通过 `keystore.properties` 或运行时配置注入
4. **所有映射表集中管理：** 服务商品牌名→URL 映射只在 `providers.json` 中定义
5. **接口先行，实现后行：** 所有 Service 层先定义 interface，再写实现，确保调用方不受实现变更影响
6. **Compose 不持有相机实例：** CameraHolder 单例在 Application 层，Composable 仅通过接口引用
